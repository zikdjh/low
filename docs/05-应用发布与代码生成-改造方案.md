# 低代码平台 Phase 2 改造方案：应用发布与挂载 + 前后端代码自动生成

> 分支：`feature/lowcode-phase-1-entity-metadata`
> 文档版本：v1.0
> 拟定日期：2026-06-24
> 进度跟踪：见 [`06-应用发布与代码生成-进度跟踪.md`](./06-应用发布与代码生成-进度跟踪.md)

---

## 1. 背景与目标

Phase 1 已经完成「实体建模 → 动态 DDL → 页面 schema 设计 → 业务应用聚合」这条设计态管线，但距离「可被终端用户日常使用 + 可被开发团队工程化接管」还差一条**发布管线**。当前主要缺口：

| # | 接缝 | 证据位置 |
|---|---|---|
| 1 | `PageSchemaService.publish` 只是状态翻转 + version 自增，没有快照、校验、审计 | `back/src/main/java/com/back/lowcode/service/PageSchemaService.java:65-67` |
| 2 | 「挂载到应用」与「自动发布」被混在一个动作里 | `back/src/main/java/com/back/lowcode/service/BusinessAppService.java:104-108` |
| 3 | 应用侧边栏直接来自 `getAppPages` 平铺，缺 Menu 模型 | `front/src/pages/lowcode/app/AppRuntime.vue:28,58-60` |
| 4 | 「页面挂到路由」靠硬编码前缀 `/leave/` | `front/src/pages/lowcode/page/PageViewer.vue:162-167` |
| 5 | 没有任何模板引擎（freemarker/velocity/mustache 全无） | 全工程检索 |
| 6 | `BusinessAppInitializer` 用字符串前缀 `leave_` 把页面塞进应用 | `back/src/main/java/com/back/lowcode/config/BusinessAppInitializer.java` |
| 7 | 「请假管理」整个业务由 Java 硬塞 | `back/src/main/java/com/back/lowcode/config/LeavePageInitializerV2.java` |
| 8 | `AppRuntime` 与 `PageViewer` 各持一份 32 项 componentMap | `AppRuntime.vue:186-219` vs `PageViewer.vue` |

本次改造的目标：

1. 建立**「发布（Release）」与「挂载（Mount）」**两个清晰的动作，通过**快照**机制将「设计态」与「运行态」解耦。
2. 引入**菜单（Menu）模型**，让业务应用具备真正可配置的导航结构，运行时支持深链接路由。
3. 引入**模板驱动的代码生成器**，把 EntityMeta / PageSchema 一键导出为可独立部署的 Spring Boot + Vue 工程。
4. 完成**请假管理**应用的迁移，删除全部硬编码 initializer，证明平台具备「自举」能力。

## 2. 总体设计

### 2.1 设计态 / 发布态 / 运行态 三层模型

```
设计态                       │ 发布态                              │ 运行态
─────────────────────────────┼────────────────────────────────────┼──────────────────────────
EntityMeta + PageSchema      │ Release(应用级发布单)              │ 终端用户访问 /run/{appCode}
ComponentDef + DictType      │  ├─ ReleaseItem(JSON 快照)         │  ├─ 后端：动态表 + 生成代码
Menu(草稿态)                  │  ├─ Menu 快照                       │  └─ 前端：菜单挂载 + Schema 渲染
                             │  └─ 代码生成产物                    │
```

- **设计态**：所有 `lc_*_meta` 表的当前可编辑状态。
- **发布态**：每次 `release` 把设计态冻结为不可变 JSON 快照，记录版本号、审计、产物。
- **运行态**：终端用户访问任何业务应用，只读取「当前 active release」的快照，**绝不读设计态**。

### 2.2 Publish 与 Mount 拆分

| 动作 | 输入 | 输出 | 是否可单独执行 |
|---|---|---|---|
| Publish | 应用 ID + 版本号增量 | `lc_release` + N×`lc_release_item` 快照 + 代码生成产物 | 是 |
| Mount | release ID + 菜单结构 | `lc_app_menu`（关联到该 release） | 是（基于已存在的 release） |
| Activate | release ID | 原子切换 `status=active`，旧 active 标记 `rolledback` | 是 |

三者通过 `release` 主键联系；Publish 默认完成 Mount + Activate，但允许"只发布不激活"用于灰度。

### 2.3 与 Phase 1 的兼容策略

- `PageSchema.status / publishedAt / version` **保留**，但语义改为「由 ReleaseService 反向维护」，前端不再直接调用 `publish` 接口。
- `BusinessAppService.assignPagesToApp` 内部的 status 写入行为**移除**，方法改名 `attachPagesToApp`，纯关系操作。
- `lc_ddl_log` 风格沿用，新增 `lc_release_log` 做发布管线审计。

## 3. 里程碑 M1：发布管线与快照（后端）

### 3.1 新增数据表

```sql
-- 应用级发布单
CREATE TABLE lc_release (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  app_code     VARCHAR(64)  NOT NULL,
  version      VARCHAR(32)  NOT NULL,           -- 语义化 1.2.0
  status       VARCHAR(16)  NOT NULL DEFAULT 'draft', -- draft | active | rolledback | failed
  notes        VARCHAR(1000),
  checksum     VARCHAR(64),                     -- 全部 item 的 sha256 汇总
  created_by   VARCHAR(64),
  created_at   DATETIME     NOT NULL,
  activated_at DATETIME,
  UNIQUE KEY uk_app_version (app_code, version)
);

-- 发布单中的每个产物快照
CREATE TABLE lc_release_item (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  release_id    BIGINT       NOT NULL,
  item_type     VARCHAR(32)  NOT NULL,   -- entity | page | component | dict | menu | codegen
  item_code     VARCHAR(128) NOT NULL,
  snapshot_json LONGTEXT     NOT NULL,
  checksum      VARCHAR(64)  NOT NULL,
  KEY idx_release (release_id),
  KEY idx_type_code (item_type, item_code)
);

-- 发布流水线审计
CREATE TABLE lc_release_log (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  release_id  BIGINT       NOT NULL,
  phase       VARCHAR(32)  NOT NULL,   -- validate | snapshot | generate | mount | activate
  result      VARCHAR(16)  NOT NULL,   -- success | failure | skipped
  message     TEXT,
  duration_ms BIGINT,
  created_at  DATETIME     NOT NULL,
  KEY idx_release (release_id)
);
```

### 3.2 ReleaseService 五阶段流水线

```
validate ─► snapshot ─► generate ─► mount ─► activate
```

| 阶段 | 职责 | 失败处理 |
|---|---|---|
| validate | 校验 layoutJson 结构、组件存在性、字段外键闭环、命名冲突 | 整体回退，release 标记 `failed` |
| snapshot | 序列化 entity/page/component/dict/menu 到 `lc_release_item` | 删除已写入 item |
| generate | 调 M3 代码生成器，产物落 `target/generated/{appCode}/{version}/` | 不阻塞 release，仅记录警告 |
| mount | 写 `lc_app_menu`（关联 release_id） | 删除已写入 menu |
| activate | 原子切换 active release | 旧 release 仍为 active |

### 3.3 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/lowcode/release/{appCode}` | 发起一次发布，body：`{ notes, versionBump: major\|minor\|patch }` |
| GET | `/lowcode/release/{appCode}` | 列出该应用历史发布 |
| GET | `/lowcode/release/{id}` | 单次发布详情 + 阶段日志 |
| GET | `/lowcode/release/{id}/items` | 查看快照清单 |
| POST | `/lowcode/release/{id}/rollback` | 回滚到指定历史 release（原子切 active） |
| POST | `/lowcode/release/{id}/activate` | 把 draft release 激活上线（灰度场景用） |

### 3.4 包结构（建议）

```
back/src/main/java/com/back/lowcode/
├── release/
│   ├── ReleaseController.java
│   ├── ReleaseService.java
│   ├── pipeline/
│   │   ├── ValidatePhase.java
│   │   ├── SnapshotPhase.java
│   │   ├── GeneratePhase.java
│   │   ├── MountPhase.java
│   │   └── ActivatePhase.java
│   ├── entity/{Release,ReleaseItem,ReleaseLog}.java
│   ├── repository/...
│   └── dto/...
```

## 4. 里程碑 M2：菜单模型与路由挂载

### 4.1 新增表

```sql
CREATE TABLE lc_app_menu (
  id               BIGINT AUTO_INCREMENT PRIMARY KEY,
  app_code         VARCHAR(64)  NOT NULL,
  menu_code        VARCHAR(64)  NOT NULL,
  parent_menu_code VARCHAR(64),
  name             VARCHAR(128) NOT NULL,
  icon             VARCHAR(64),
  sort_order       INT          NOT NULL DEFAULT 0,
  menu_type        VARCHAR(16)  NOT NULL,    -- page | external | group
  target_page_code VARCHAR(128),
  target_url       VARCHAR(500),
  visible_roles    VARCHAR(500),             -- JSON 数组
  release_id       BIGINT,                   -- NULL = 设计态草稿
  created_at       DATETIME     NOT NULL,
  updated_at       DATETIME     NOT NULL,
  UNIQUE KEY uk_app_menu (app_code, menu_code, release_id)
);
```

### 4.2 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/lowcode/app/{appCode}/menu` | 取当前 active release 的菜单树（终端用户使用） |
| GET | `/lowcode/app/{appCode}/menu/draft` | 取草稿菜单树（设计器使用） |
| PUT | `/lowcode/app/{appCode}/menu/draft` | 更新草稿菜单（全量提交） |
| POST | `/lowcode/app/{appCode}/menu/reorder` | 拖拽排序（局部） |

### 4.3 前端改造

| 改造点 | 文件 | 操作 |
|---|---|---|
| 抽出公共 `SchemaRenderer` | 新增 `front/src/components/lowcode/SchemaRenderer.vue` | 把 32 项 componentMap 收敛到一处 |
| `AppRuntime` 侧栏 | `front/src/pages/lowcode/app/AppRuntime.vue` | 改读菜单树，支持多级展开 / 图标 |
| `AppRuntime` 路由 | `front/src/router/modules/runtime.ts` | `/run/:appCode/:pageCode?`，支持深链 |
| `PageViewer` 监听 | `front/src/pages/lowcode/page/PageViewer.vue` | 删 `route.path.startsWith('/leave/')` 硬编码，监听 `params.pageCode` |
| 新增菜单编辑器 | `front/src/pages/lowcode/app/AppMenuEditor.vue` | 树形拖拽 + 图标选择 + 关联 page |

### 4.4 路由挂载两种形态

- **运行时挂载（默认）**：`/run/:appCode/:pageCode?`，由 `AppRuntime` 渲染菜单 + Schema。新应用零代码上线。
- **独立路由挂载（可选）**：M3 代码生成可产出 `front/src/router/modules/{appCode}.ts` 与各 `.vue` 文件，等同请假管理那种「看起来像原生页面」的形态。

## 5. 里程碑 M3：前后端代码自动生成

### 5.1 引入 FreeMarker

- 后端 pom 加入 `org.freemarker:freemarker`。
- 模板目录：`back/src/main/resources/codegen/templates/`

```
codegen/templates/
├── java/
│   ├── controller.java.ftl
│   ├── service.java.ftl
│   ├── repository.java.ftl
│   ├── entity.java.ftl
│   └── dto.java.ftl
├── sql/
│   └── ddl.sql.ftl
├── vue/
│   ├── list-page.vue.ftl
│   ├── form-page.vue.ftl
│   ├── detail-page.vue.ftl
│   ├── router.ts.ftl
│   ├── api.ts.ftl
│   └── menu.ts.ftl
└── openapi/
    └── spec.yaml.ftl
```

### 5.2 后端生成物（per EntityMeta）

为每个已发布实体生成传统 Spring Boot 工程代码（仅作产物归档，不替换运行时动态数据通道）：

- `entity/{EntityName}.java` —— JPA 实体（字段类型映射、外键 `@ManyToOne`）
- `repository/{EntityName}Repository.java`
- `service/{EntityName}Service.java` —— CRUD + 校验 + 分页
- `controller/{EntityName}Controller.java` —— REST 端点
- `dto/{EntityName}DTO.java` + `{EntityName}Query.java`
- `sql/V_{releaseId}__{appCode}.sql` —— 整应用 DDL

### 5.3 前端生成物（per PageSchema）

- `views/{appCode}/{PageName}.vue` —— 由 layoutJson 静态展开为 Vue 模板
- `api/{appCode}/{entityCode}.ts` —— axios 接口
- `router/modules/{appCode}.ts` —— 应用路由
- `menu/{appCode}.ts` —— 静态菜单常量

### 5.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/lowcode/codegen/preview/{releaseId}` | 试生成，返回 `{ path → content }` 内存预览 |
| POST | `/lowcode/codegen/build/{releaseId}` | 产出落 `target/generated/{appCode}/{version}/` |
| GET | `/lowcode/codegen/download/{releaseId}` | 打 zip 下载 |

### 5.5 设计原则

- **生成物默认不进 git**：放 `target/generated/`，加入 `.gitignore`，作为可下载工件。
- **不直接覆盖运行代码**：开发者主观决定是否合入工程。
- **每次 release 自动 build 一次**：作为「这次发布的工程化产物归档」。
- **保留 EntityMeta 为唯一真源**：生成代码失效时，重新发布即重新生成。

### 5.6 前端 UI

新增 `/lowcode/release` 页面：

- 左：应用列表
- 右：版本时间线（active / draft / rolledback / failed 用 Tag 区分）
- 详情：阶段日志、快照清单、代码预览（左树 + 右 monaco 高亮）、下载 zip、回滚
- 设计器顶栏新增 **「发布」** 按钮 → wizard：勾选 entity/page → 选 versionBump → 实时显示阶段进度

## 6. 里程碑 M4：请假应用迁移（自举验证）

### 6.1 目标

证明新管线能反向兼容现有样例，并删除全部硬编码 initializer。

### 6.2 步骤

1. 导出当前请假管理应用为 `seed/leave_management-v1.0.0.json`（应用级 release 快照），放 `back/src/main/resources/seed/`。
2. 新增 `SeedReleaseLoader`：启动时若库内无 `leave_management` 的 active release，则把 seed 当作 release 灌入 `lc_release` / `lc_release_item`，再调 mount + activate。
3. 删除以下硬编码：
   - `LeavePageInitializer.java`
   - `LeavePageInitializerV2.java`
   - `LeaveDataInitializer.java`（保留业务种子数据部分，删除页面 / 菜单生成）
   - `BusinessAppInitializer.java`
4. 收缩 `front/src/router/modules/leave.ts` —— 仅保留管理员后台子页；终端用户走 `/run/leave_management/*`。
5. 删除 `PageViewer.vue:162-167` 的 `route.path.startsWith('/leave/')` 硬编码。

### 6.3 验收

- 全新初始化数据库后，启动应用，能看到 `leave_management` 出现在应用列表，菜单完整。
- 终端用户访问 `/run/leave_management` 能用全部功能（学生申请、教师审批、辅导员处理、管理员统计）。
- 项目内 grep `leave` 关键字，只剩业务字典 / 种子数据，无页面构造逻辑。

## 7. 交付顺序与并行机会

| 里程碑 | 估算 | 依赖 | 用户感知价值 |
|---|---|---|---|
| M1 发布管线 + 快照 | ~3 周 | 无 | 设计态变更不再实时影响线上；可回滚 |
| M2 菜单 + 路由挂载 | ~2 周 | M1 快照 | 应用侧栏可配置，可深链接 |
| M3 代码生成器 | ~3 周 | M1 快照 | 平台不再是黑盒，可一键导出工程 |
| M4 请假应用迁移 | ~1 周 | M1-M3 | 自举闭环，删 ~2000 行硬编码 |

并行机会：**M2 与 M3 在 M1 完成后可并行**。

## 8. 早期决策与约束

| 决策点 | 选项 | 推荐 | 理由 |
|---|---|---|---|
| 代码生成产物去向 | 进 git / 不进 git | **不进 git** | 避免与设计态双源 |
| 模板引擎 | FreeMarker / Velocity / Mustache | **FreeMarker** | Spring 生态成熟、依赖小 |
| Release 快照是否含业务数据 | 含 / 不含 | **不含** | Release 是结构快照；数据走独立备份 |
| 版本号策略 | 自增 / 语义化 / git-hash | **语义化 + checksum** | 用户可读 + 可溯源 |
| `PageSchema.publishedAt` 字段 | 保留 / 删除 | **保留** | 反向由 ReleaseService 维护，前端只读 |
| 发布失败的回滚粒度 | 阶段级 / 整体级 | **整体级 + 阶段标记** | 简单可靠；生成阶段失败不阻塞 release |

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 历史 PageSchema 数据量大，全量快照膨胀 `lc_release_item` | 启用按 sha256 去重，相同 snapshot 复用 |
| 代码生成模板与 EntityMeta 字段类型不匹配 | M3 第一周专门做类型映射矩阵 + 单测 |
| 请假应用迁移期间双轨运行 | M4 设 Feature Flag `lowcode.runtime.useSeedRelease=true/false`，开关切换 |
| FreeMarker 模板被恶意篡改造成 SSTI | 模板目录置为 classpath 只读资源，不开后台编辑 |

## 10. 验收标准

完成 Phase 2 后，应当满足：

- [ ] 任何 EntityMeta / PageSchema 修改不影响在线运行，必须通过「发布」才能上线。
- [ ] 任意历史 release 可一键回滚，回滚后 5 秒内终端用户可见旧版本。
- [ ] 业务应用的菜单可在管理端拖拽配置，运行时自动渲染。
- [ ] 任意 release 可下载完整工程 zip（Spring Boot + Vue 双端），导入 IDE 后能编译通过、连接外部数据库后能运行。
- [ ] 项目代码中无 `leave_` 前缀的页面 / 菜单硬编码。
- [ ] `AppRuntime.vue` 与 `PageViewer.vue` 共用唯一 `SchemaRenderer`。
- [ ] 完整发布流水线审计可在 `/lowcode/release/{id}` 查看阶段日志。
