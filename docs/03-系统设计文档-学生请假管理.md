## 二、工作流引擎设计

### 2.1 设计思路

由于项目定位为轻量级低代码平台（对标 Retool/Appsmith），不引入 BPMN 重量级引擎。采用 **自定义状态机 + 任务表** 的轻量方案，满足"学生请假审批"二节点流程。

### 2.2 核心类设计

```
WorkflowService
├── startWorkflow()      → 创建实例 + 第一个审批任务
├── approve()            → 当前节点通过，流转到下一节点 or 完成
├── reject()             → 当前节点驳回，流程终止
├── cancel()             → 发起人撤回
├── getProgress()        → 查询流程进度
├── getPendingApprovals()→ 按角色查待审批列表
└── getApprovalNodes()   → 获取审批节点定义
```

### 2.3 流程配置示意

```java
// 审批节点定义（请假流程）
private static final List<Map<String, String>> LEAVE_APPROVAL_NODES = List.of(
    Map.of("name", "辅导员审批", "role", "counselor"),
    Map.of("name", "系主任审批", "role", "dept_head")
);
```

**低代码平台优势**：审批节点改为配置而非硬编码，修改流程只需修改此 List，无需改动审批逻辑代码。

### 2.4 工作流核心配置步骤

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 定义审批节点 | 配置节点名称和审批人角色 |
| 2 | 用户发起申请 | 自动创建 `lc_workflow_instance` 和第一个 `lc_workflow_task` |
| 3 | 辅导员审批 | 系统按当前节点角色 `counselor` 展示待审批列表 |
| 4 | 通过 → 流转 | 创建下一节点 `lc_workflow_task`（角色 `dept_head`） |
| 5 | 系主任审批 | 系统按当前节点角色 `dept_head` 展示待审批列表 |
| 6 | 通过 → 完成 | 流程状态改为 `approved`，请假记录状态同步更新 |
| 7 | 驳回 → 终止 | 任一节点驳回即终止，请假记录状态改为 `rejected` |

### 2.5 流程状态转换图

```
        startWorkflow()
             │
     ┌───────▼────────┐
     │  pending(进行中) │
     └───┬───────┬─────┘
         │       │
    approve()  reject()     cancel()
         │       │             │
    ┌────▼──┐ ┌─▼──────┐  ┌──▼──────┐
    │approved│ │rejected│  │cancelled│
    └────────┘ └────────┘  └─────────┘
```

## 六、低代码平台核心能力体现

### 6.1 可视化实体建模

请假申请实体通过系统启动时自动创建，体现低代码平台"定义即建表"的核心能力：

```java
// LeaveDataInitializer.java — 启动时自动创建实体和字段
EntityMeta entity = EntityMeta.builder()
    .code("leave_application").name("请假申请")
    .tableName("lc_leave_application").build();
// ... 定义 8 个字段 ...
ddlService.createTable(entity.getId()); // 自动建表
```

### 6.2 通用 CRUD 引擎复用

请假数据的所有增删改查通过 `DynamicDataService` 统一处理，无需为请假表编写 SQL：

```java
// 查询请假记录 → 一行调用，自动分页、过滤
dynamicDataService.listData("leave_application", page, pageSize, filters);

// 创建请假记录 → 自动按 FieldMeta 映射列
dynamicDataService.createData("leave_application", data);
```

### 6.3 服务可视化配置思路

请假管理 11 个 REST 端点均遵循低代码"简易编码"思路：
- 数据查询服务：配置实体编码 + 过滤条件，无需写 SQL
- 数据源服务：配置化返回，前端组件通过属性绑定
- 数据库操作服务：封装为 RESTful 接口，可被可视化组件调用

### 6.4 角色与权限

通过 Spring Security + JWT 实现：
- 3 个业务角色自动初始化（student/counselor/dept_head）
- 演示账户自动创建（zhangsan/fdy/xizhuren）
- 前端页面按角色区分可访问模块
- 后端 API 按角色校验审批权限
